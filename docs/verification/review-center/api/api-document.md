### ApiDocument

#### Verification Approach

`ApiDocument` is verified with tests defined in `ApiDocumentTests.cs`. The tests start the real application in process
(`TestWebApp`) over a temporary database, fetch `/api/openapi.json` with an HTTP client that sends no token, and parse or
compare the JSON. The snapshot test compares the document with `docs/api/openapi.json` after the line endings are
normalized; when the API changes on purpose, the test is run once with the environment variable
`REVIEWCENTER_UPDATE_OPENAPI` set to `1` to write the new snapshot, which is then reviewed and kept.

#### Test Environment

N/A - standard test environment (a temporary database is created by each test). The snapshot test reads
`docs/api/openapi.json` from the repository root.

#### Acceptance Criteria

- All tests pass with zero failures.
- The document is served without a token, has the fixed version, no server address, the bearer scheme, only paths under
  `/api/`, and one security requirement on every operation.
- Two applications produce the same document.
- The generated document equals the snapshot that is kept in the documentation.

#### Test Scenarios

**ApiDocument_Get_NoToken_DescribesTheApiWithBearerScheme**: The document is requested without a token and parsed. It is
served with 200, has the version `1`, lists no server, has an HTTP bearer security scheme, lists the project and
attestation paths, lists only paths that start with `/api/` and not the address of the document itself, and has exactly
one security requirement on every operation. This scenario is tested by
`ApiDocument_Get_NoToken_DescribesTheApiWithBearerScheme`.

**ApiDocument_Get_TwoApplications_AreIdentical**: The document is generated by two separately started applications. The
two texts are the same, so the snapshot does not depend on the machine, the host address, or the run. This scenario is
tested by `ApiDocument_Get_TwoApplications_AreIdentical`.

**ApiDocument_Get_MatchesCommittedSnapshot**: The generated document is compared with `docs/api/openapi.json`. The two
are the same, so a change of the API that was not documented fails the test. This scenario is tested by
`ApiDocument_Get_MatchesCommittedSnapshot`.
