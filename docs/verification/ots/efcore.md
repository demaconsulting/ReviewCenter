## Entity Framework Core Verification

This document provides the verification evidence for the Entity Framework Core OTS software item, together with its
SQLite provider. Requirements for this OTS item are defined in the EF Core OTS Software Requirements document.

### Required Functionality

Entity Framework Core maps the entity classes of the Storage subsystem to database tables, including keys that span
a project and a review identifier and binary columns for file content, and the SQLite provider creates the database
file with those tables and lets the database enforce uniqueness and relationships. Passing tests confirm both
function correctly.

### Verification Approach

Entity Framework Core has no self-validation mode and is verified by the project's own tests, which run the real
library against real SQLite database files in a private temporary folder; no in-memory substitute is used, because
the behavior of the real provider is what is verified. Each scenario names a specific test method that depends on
the library under verification. A passing pipeline run for all scenarios constitutes evidence that both
requirements are satisfied.

### Test Scenarios

#### ReviewStore_AddProjectAsync_ValidProject_RoundTrips

**Scenario**: A project entity is saved through the context and read back through a new context.

**Expected**: The values are returned unchanged and the identity was generated by the database.

**Requirement coverage**: `ReviewCenter-OTS-EfCore-Mapping`.

#### ReviewStore_AddReviewAsync_BinaryCrLfAndEmptyFiles_StoresBytesVerbatim

**Scenario**: A review with files of binary content, carriage returns, and no content is saved and read back.

**Expected**: Every byte array is returned unchanged.

**Requirement coverage**: `ReviewCenter-OTS-EfCore-Mapping`.

#### ReviewStore_AddReviewAsync_SameIdInTwoProjects_KeepsThemApart

**Scenario**: Reviews with the same identifier are saved in two projects.

**Expected**: The composite key allows both and each is read back from its own project.

**Requirement coverage**: `ReviewCenter-OTS-EfCore-Mapping`.

#### DatabaseSetup_EnsureCreated_MissingFolder_CreatesFolderFileAndTables

**Scenario**: The database is created at a path in a folder that does not exist.

**Expected**: The file exists and the tables for projects, reviews, and review files can be queried.

**Requirement coverage**: `ReviewCenter-OTS-EfCore-Sqlite`.

#### ReviewStore_AddReviewAsync_DuplicateKey_ThrowsReviewIdDuplicate

**Scenario**: A review is saved with a key that already exists.

**Expected**: The database refuses it with a unique-key error, which the store reports as a duplicate.

**Requirement coverage**: `ReviewCenter-OTS-EfCore-Sqlite`.

#### ReviewStore_AddReviewAsync_UnknownProject_IsNotStored

**Scenario**: A review is saved for a project that does not exist.

**Expected**: The database refuses it because of the relationship to the project and nothing is stored.

**Requirement coverage**: `ReviewCenter-OTS-EfCore-Sqlite`.
